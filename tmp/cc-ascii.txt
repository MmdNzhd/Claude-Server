11|## Architecture
12|
13|```
14|Laptop (Windows/Mac)
15|  connect.bat / connect.sh
16|    reverse SSH tunnel  ->  server port 20000 + UID
17|    pushes ~/.claude-connect.conf (GIT_MODE, ACTIVE_MOUNT, TUNNEL_PORT)
18|
19|Server (Linux)
20|  claude-mount up <id>  ->  SSHFS ~/mounts/<id>  <- laptop folder via tunnel
21|  Cursor/VS Code Remote SSH opens vscode-remote://ssh-remote+claude-server/...
22|```
23|
24|Each `ssh` call opens a new TCP connection (no multiplexing). Client scripts auto-update from the server bundle (`sudo claude-server deploy-client-bundle`) on connect when a newer version is published.

28|## Smart vs Sepidz
29|
30|One client codebase. Two publish packages (same scripts; different server IP):
31|
32|| Package | ZIP name | Server IP | README in ZIP |
33||---------|----------|-----------|---------------|
34|| **Smart** | `claude-code-client-YYYYMMDD.zip` | `192.168.210.240` | `README.txt` from `publish/README.txt` |
35|| **Sepidz** | `claude-code-sepidz-YYYYMMDD.zip` | `192.168.250.70` | `claude-code/README.md` from `publish/README-sepidz.txt` + `designer/` |
36|
37|Do not mix Smart and Sepidz folders on one laptop for the same workflow - check the IP in the connect header. Logging policy (server-only `~/.claude/logs/`) is identical on both sites.
38|
39|Publish: `publish\publish.bat` (or `-SmartOnly` / `-SepidzOnly`). Admin: `sudo claude-server deploy-client-bundle` on each server.
40|## Single project per session
41|
42|- `ACTIVE_MOUNT` in `~/.claude-connect.conf` names the current project id.
43|- `claude-mount up <id>` mounts only that project.
44|- **Other already-mounted projects are not unmounted** on connect.
45|- On disconnect: **only the current project** is unmounted; `.git` is restored on the laptop.
46|
47|Project definitions in `~/.claude-mounts.d/<id>.conf` are never deleted when switching projects.
48|
49|**Mac vs Windows paths:** each mount conf stores a laptop `rpath`. Windows paths (`D:/...`) are purged automatically on Mac connect (and vice versa) so the project list stays usable.

53|## GIT_MODE (OFF / HIDE / SLOW)
54|
55|| Mode | Behavior |
56||------|----------|
57|| **off** (default) | No `.git` rename on laptop; use `laptop-exec git` on the server for git commands |
58|| **hide** (HIDE) | Rename `.git` -> `.git.server-session` on laptop before SSHFS (faster mount) |
59|| **server** (SLOW) | Keep `.git` on SSHFS mount; full git over network (slow) |
60|
61|| Key | When |
62||-----|------|
63|| `g` | Project menu - toggle mode before session |
64|| `G` | Active session - toggle + remount |
65|
66|Config: `~/.config/claude-connect/git.conf` (laptop) pushed to `~/.claude-connect.conf` on server.
67|
68|If hide fails (Cursor locks `.git`): close Remote SSH / git on laptop, then press `G` to remount.

72|## Session keys
73|
74|| Key | Action |
75||-----|--------|
76|| `R` | Reconnect tunnel |
77|| `Q` / Enter | Disconnect (editor down, mount down, restore `.git`) |
78|| `G` | Change git mode + remount |
79|| `O` | Relaunch Cursor on correct remote folder |
80|| `P` | Push Cursor golden auth (bootstrap only) |
81|| `M` | Project menu after disconnect |
82|| `C` | Connect again after disconnect |
83|| `X` | Exit |

87|## Cursor profiles (Windows)
88|
89|- **Personal:** `%APPDATA%\Cursor` - never touched by connect scripts.
90|- **Server:** `%LOCALAPPDATA%\ClaudeServerCursorProfile` via `--user-data-dir`.
91|- Title bar shows `[Claude Server]` for server profile windows.
92|- `cursor-auth-laptop.ps1` merges auth keys into server profile SQLite (never closes Cursor).
93|
94|If Cursor opens **Agent home** instead of the project folder, check the **server** connect log (see [Logging](#logging)). v20260717.8+ uses `--new-window` when not on the correct `folder-uri`.
95|
96|After auth sync, if Chat messages fail or Cursor asks to log in: **Developer \u2192 Reload Window** in the `[Claude Server]` profile window.
97|Connect scripts keep the profile `machineid` file aligned with the server golden identity (required for login to stick).

101|## Cursor profiles (Mac)
102|
103|- **Personal:** `~/Library/Application Support/Cursor` - never touched by connect scripts.
104|- **Server:** `~/Library/Application Support/ClaudeServerCursorProfile` via `--user-data-dir`.
105|- Title bar shows `[Claude Server]` for server profile windows.
106|- `git-mode.sh` merges golden auth into server profile `state.vscdb` on each connect (requires `sqlite3`).
107|
108|**Remote SSH extension:** install **`anysphere.remote-ssh`** only. Uninstall Microsoft's `ms-vscode-remote.remote-ssh` if present (Extensions \u2192 search `@id:anysphere.remote-ssh`).
109|
110|**Mac socket bug:** profile template sets `"remote.SSH.useLocalServer": false`. If Remote SSH still fails with `listen EINVAL`, run once in Terminal then fully quit Cursor:
111|
112|```bash
113|launchctl setenv TMPDIR /tmp
114|```
115|
116|Connect also sets `TMPDIR=/tmp` automatically when needed.
117|
118|After auth sync, if Chat messages fail or Cursor asks to log in: **Developer \u2192 Reload Window** in the `[Claude Server]` profile window.
119|Connect scripts keep the profile `machineid` file aligned with the server golden identity (required for login to stick).
120|
121|If Cursor opens **Agent home** instead of the project folder, press **`O`** in the connect menu or reconnect with v20260717.8+.

125|## Logging
126|
127|**Policy (v20260717.24+):** durable logs live **only on the server**. The laptop keeps a short-lived temp buffer and deletes it when the session ends (or after sync).
128|
129|| Where | Path |
130||-------|------|
131|| Server (durable) | `~/.claude/logs/connect-YYYYMMDD.log` |
132|| Server (SSH diag) | `~/.claude/logs/laptop-ssh-diag-latest.txt` (+ timestamped copies) |
133|| Laptop Mac (temp) | `/tmp/claude-connect.*.log` via `mktemp` \u2014 deleted after flush |
134|| Laptop Windows (temp) | `%TEMP%\claude-connect-<PID>.log` \u2014 deleted on `Close-ConnectLog` |
135|
136|Legacy laptop paths are removed on start: `~/.config/claude-connect/logs/` and any old `connect.log` beside `connect.bat`.
137|
138|**Retention:** files under `~/.claude/logs/` older than **1 day** are deleted:
139|
140|- Client: `find \u2026 -mtime +1 -delete` on each sync flush
141|- Server: `/usr/local/bin/claude-connect-logs-cleanup` via `/etc/cron.d/claude-connect-logs` (hourly, as root)
142|
143|### What a full log contains (v20260717.24+)
144|
145|Each connect run uploads a timeline to `~/.claude/logs/connect-YYYYMMDD.log`. Look for these markers in order:
146|
147|| Marker | Meaning |
148||--------|---------|
149|| `======== session start` | Connect started (version, user, pid) |
150|| `======== CONTEXT phase=startup` | Early snapshot (host, users, paths) |
151|| `STEP begin/end` | Named setup steps + duration ms |
152|| `======== CONTEXT phase=server_ready` | Tunnel port, git mode, server user known |
153|| `======== CONTEXT phase=project_selected` | Chosen project id + laptop/server paths |
154|| `SESSION_LOOP begin` + `CONTEXT phase=session_loop` | Mount/auth/editor cycle (reconnect bumps iter) |
155|| `SSH_BEGIN` / `SSH_END` / `SSH_TIMEOUT` | Every remote `ssh`/`sshx` call |
156|| `MOUNT` / `PERF[mount_*]` | SSHFS up result + timing |
157|| `AUTH_*` / `FOLDER_CHECK` / `LAUNCH_*` | Cursor auth + open folder decisions |
158|| `STATUS` / `HEARTBEAT` | Live tunnel/editor state while session open |
159|| `LAPTOP_SSH_DIAG` | Reverse-SSH failure details (also `laptop-ssh-diag-latest.txt`) |
160|| `RECOVERY_*` | Auto-heal after tunnel drop |
161|| `======== CONTEXT phase=cleanup` / `session_end` | Disconnect snapshot |
162|| `======== session end` | Final line before temp buffer wiped |
163|
164|`CONTEXT` lines always include: `REMOTE_USER`, `LAPTOP_USER`, `SERVER_IP`, `PORT`, `CONNECT_VERSION`, `GIT_MODE`, `ACTIVE_MOUNT`, editor flags, and `local_cfg` (DEBUG).
165|
166|**Admin read (on server):**
167|
168|```bash
169|sudo-from-laptop cat /home/<user>/.claude/logs/connect-$(date +%Y%m%d).log
170|sudo-from-laptop cat /home/<user>/.claude/logs/laptop-ssh-diag-latest.txt
171|```
172|
173|### Performance marks
174|
175|Cheap `PERF[...]` lines are emitted by default across mount, auth, launch, and diagnostic. Disable with:
176|
177|```
178|set CLAUDE_CONNECT_PERF_LOG=0
179|```
180|
181|Verbose launch diagnostics (WMI snapshots) only when debugging slowness:
182|
183|```
184|set CLAUDE_CONNECT_VERBOSE_LAUNCH=1
185|```
186|
187|Summarize a **copied** session log on Windows (download from server first, or capture the temp buffer during an open session):
188|
189|```bat
190|powershell -NoProfile -File scripts\client\tests\parse-connect-perf.ps1 -LogPath path\to\connect-YYYYMMDD.log
191|```
192|
193|**Expected gates after Tier A fixes:** cold `Opening Cursor` under 8000 ms, skip path under 1500 ms, `SNAPSHOT` count 0 unless verbose mode.
194|
195|Useful lines:
196|
197|```
198|[INFO]  STEP end: Opening Cursor ok ms=...
199|[DEBUG] PERF[launch_total] ms=... cim_total=...
200|[DEBUG] PERF[session_open_summary] ms=0 mount_ms=... auth_ms=... open_ms=... diag_ms=...
201|[INFO]  LAUNCH_SKIP: already on correct folder - keeping Cursor open
202|[INFO]  PROJECT: id=...
203|[INFO]  ACTIVE_MOUNT: ...
204|[DEBUG] FOLDER_CHECK: on_folder=... agent_home=...
205|[INFO]  STATUS: [... | Cursor]
206|```

210|## Mac: Remote Login / reverse SSH
211|
212|The reverse tunnel needs the **server** to SSH into the Mac as `LAPTOP_USER` (`whoami` short name, e.g. `mohmmad`). That is separate from the **server Linux username** (e.g. `mohammad`).
213|
214|1. System Settings \u2192 Sharing \u2192 **Remote Login** = On
215|2. Allow the Mac account shown by `whoami`, or **All users** (Sharing UI often shows Full Name \u2014 allow that row if listed)
216|3. If key auth still fails, leave connect running until it finishes; diagnostics upload to `~/.claude/logs/laptop-ssh-diag-latest.txt` on the server
217|
218|Admin password is requested **at most once** per connect run (45s timeout). Destructive Remote Login cycling is skipped when login is already on.
219|

222|## Stale / foreign session heal
223|
224|If `~/.claude-connect.conf` points at another laptop user but the tunnel port is **not** listening, connect clears the stale conf and continues (avoids \u201cforeign session\u201d dead-ends after a crash or shared account mistake).

249|## Troubleshooting
250|
251|| Symptom | Fix |
252||---------|-----|
253|| Join-Path ChildPath prompt | Old `connect.ps1` - copy full `windows\` folder from latest ZIP |
254|| connect.bat OUTDATED | Missing `connect-ui.ps1` or wrong version in header |
255|| Cursor Agent home, not project | Update to v20260717.24+, check server `~/.claude/logs/connect-*.log`, press `O` |
256|| Cursor Chat cannot send (Mac/Win) | Reconnect, then **Developer \u2192 Reload Window** in `[Claude Server]` window |
257|| Mac Remote SSH `listen EINVAL` | Update to v20260717.24+; or `launchctl setenv TMPDIR /tmp` + quit Cursor fully |
258|| Mac Remote SSH timeout | Use `anysphere.remote-ssh` (not Microsoft extension) |
259|| Laptop SSH key / Permission denied (Mac) | Enable Remote Login for the Mac account / All users; then read `~/.claude/logs/laptop-ssh-diag-latest.txt` on server |
260|| Empty project list on Mac after Windows session | Auto-adds / purges incompatible `rpath`; add the Mac folder once |
261|| Stale \u201cforeign session\u201d / wrong LAPTOP_USER | Auto-cleared when tunnel port is down; reconnect |
262|| No `connect.log` beside bat | Expected \u2014 logs are on the server only (v20260717.24+) |
263|| git hide failed | Close Cursor/git on laptop, press `G` |
264|| Tunnel drops | Auto-reconnect; editor not re-opened on reconnect |
